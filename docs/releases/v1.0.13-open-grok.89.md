# Open Grok v1.0.13-open-grok.89

This release adds a guided custom-provider wizard, parses OpenCode Go
reasoning-effort metadata, and removes the Antigravity CLI subagent
integration. Test suites across the touched crates now pass cleanly on
machines where the macOS trust store made storage tests flaky.

- Add a five-step custom-provider wizard (`/provider`, also `/providers` and
  `/custom-provider`): server address, optional key, wire format (Chat
  Completions / Responses / Messages), live model discovery, and a save
  summary that batch-upserts `[model.*]` entries. A Settings trigger row
  opens the same flow, with secret redaction and stale-result handling.
- Map models.dev `reasoning_options` effort entries for OpenCode Go onto the
  reasoning-effort menu. Absent or non-effort shapes stay fail-closed;
  no default effort is invented.
- Remove the Antigravity CLI (`agy`) subagent backend entirely: the
  `antigravity:*` model slugs, the out-of-process runner and heartbeats, the
  `/usage` quota section, the `[antigravity]` config table, and the two
  Settings rows (`Antigravity subagents`, `Antigravity full access`). The
  built-in in-process subagent, swarm, and workflow paths are unchanged.
- Make the upload-queue and S3 tests independent of the OS trust store:
  building an HTTP client loads platform roots, which on macOS can take tens
  of seconds and intermittently parse zero certificates (poisoning every
  later AWS SDK client build in debug profiles). Tests now share a
  TLS-root-free client for their plaintext loopback servers, via the same
  client-injection seams production callers use.
- Defer provider HTTP client construction to first use. Every session actor
  eagerly built eleven provider-catalog `reqwest` clients, so actor startup
  (and every session test with an internal deadline) stalled behind the
  macOS trust-store load; the clients now initialize on their first real
  network fetch, keeping full native roots for production traffic.
- Give test actors a dedicated empty working directory and let them opt out
  of the project-discovery filesystem watcher: `run_session` starts an
  FSEvents stream synchronously, and `fseventsd` latency under unrelated
  machine I/O was blowing tests' five-second internal deadlines. Also stop
  the terminal group-kill regression test from racing login-shell startup
  against its one-second timeout, and serialize the two Steer-queue tests
  that share a process-global setting cache.
- Close pre-existing Settings contract gaps: registry defaults, kind
  membership, keyboard/mouse coverage, and typed setters for
  `codex_persistent_mode`, `codex_guardian_review`, `stream_tool_calls`, and
  `features.context_management.experimental_mode`; reserve the `/mission`
  and `/sandbox` pager builtins in the shell's collision contract; and make
  the status-line color assertions match the renderer's terminal color-level
  quantization so they hold under `NO_COLOR`.

Validation: full `cargo test` for `xai-file-utils` (218 passed, run twice),
`xai-grok-shared`, `xai-grok-subagent-resolution`, `xai-grok-pager` (9308
lib tests plus 320 settings e2e tests), and `xai-grok-shell` pass in an
isolated `OPENGROK_HOME`, including under a `NO_COLOR` environment. Every
test that failed deterministically before the fixes above now passes
serially and in the parallel five-package run; the remaining known
sensitivity is disk contention on heavily loaded machines, where the
git-worktree and search-bootstrap tests can still exceed their (now
generous) deadlines under full-suite parallelism.
